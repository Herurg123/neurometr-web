# latest.json: untrusted catalog pointer specification (v0.1.0)

The pointer is **not signed** and does not establish any trust. It is only a locator to an immutable, signed manifest. A client must not execute, upload, follow redirects to other origins, or fetch arbitrary URLs supplied in an imported diagnostic JSON.

## Exact JSON object

\`\`\`json
{
  "kind": "neurometr.catalog-pointer",
  "schema_version": "0.1.0",
  "manifest_path": "/data/catalog/manifests/2026.11.11.1/manifest.json"
}
\`\`\`

The URI must be a relative-to-origin *absolute path* matching \`latest-pointer.schema.json\`. It cannot contain a scheme, host, query, fragment, percent encoding, backslash, \`..\`, arbitrary path traversal or unknown prefix. The origin itself is a preconfigured HTTPS allowlist value inside Agent, **never** taken from this file or from a diagnostic JSON.

The version in \`manifest_path\` must match \`manifest.catalog_version\`. A client checks compatibility before activation; a valid pointer is insufficient without verified signature. HTTPS certificate validation and strict redirects/no-cross-origin policy are required. Do not infer successful network or regional access from a lone HTTP status.

## Target publication order

1. Upload immutable versioned \`catalog.json\`.
2. Upload immutable \`manifest.json\` with \`manifest.json.sig\` generated by Ed25519 over the **exact manifest bytes**. Signature is stored separately; no JSON canonicalization.
3. Validate byte count, SHA-256, schema and compatibility.
4. Update \`latest.json\` **last**, using atomic rename if the server supports it.

If any step fails, discard candidate, retain last-known-good; if none, use bundled catalog. Automatic downgrade is forbidden. Intentional rollback uses a newly signed higher-version manifest pointing to an already verified old payload.

**B1 scope:** schema and explanatory contract only. No network implementation, signature generation/verification, production keys or deploy. B4 and Agent own the runnable trust pipeline.
